## 2. 機能詳細

### 2.1 問い合わせフォーム機能

- ログイン不要で、誰でもアクセス・送信できる
- 入力項目：氏名(必須)、メールアドレス(必須)、電話番号(任意)、カテゴリ(必須・選択式)、問い合わせ内容(必須)
- カテゴリの選択肢：「料金プラン」「使い方」「解約」「不具合」「その他」の5つ(SaaS型サブスクリプションサービスを想定)
- スマートフォン・タブレット・PCの画面幅に対応する(レスポンシブ対応)
- 不正利用対策として、同一IPからの`POST /inquiries`を1分間に5回までに制限する(Rack::Attack)。これは想定利用(月間300件程度、1日あたり10件程度)を妨げる意図ではなく、フォームの誤操作の連続送信や自動投稿(bot)対策を目的とする
  - AWSデプロイ時、リバースプロキシ(nginx等)経由になる場合は、アクセス元IPの取得方法(X-Forwarded-Forの信頼設定)を別途確認する必要がある

### 2.2 スタッフログイン機能

- メールアドレスとパスワードでログインする
- パスワードは`has_secure_password`によりハッシュ化して保存する
- 未ログインの状態でボード画面等にアクセスした場合、ログイン画面にリダイレクトする
- スタッフアカウントの新規登録画面は設けない。アカウントはRailsのコンソールまたはseedデータにより事前に作成する
- ログアウトボタンから、いつでもセッションを終了できる(2.2の続きとして15番のログアウト機能に対応)

### 2.3 ボード表示機能

- 「未対応」「対応中」「完了」の3カラムで問い合わせを表示する
- 各カードには氏名・カテゴリ・優先度・担当者を表示する
- 受付から24時間以上「未対応」のカードは赤系の色で強調表示する
- 各カラムは20件ずつ表示し、それ以上ある場合は「もっと見る」ボタンで追加読み込みする(削除機能がなく「完了」カラムが際限なく増える設計のため)

### 2.4 ステータス変更機能

- PC：カード(問い合わせ)をドラッグ&ドロップして別カラムに移動すると、ステータスが自動更新される
- スマートフォン：ドラッグ&ドロップの代わりに、ボード画面のカード上のプルダウンでステータスを変更できる(詳細画面内のプルダウンからも同様に変更可能)
- ステータスはどのカラム間でも自由に移動でき、後戻り(例:対応中→未対応)も許可する
- ただし「完了」への変更は担当者設定を必須とする(担当者不明のまま完了すると責任の所在が曖昧になるため)。担当者未設定のまま「完了」にしようとした場合はエラーにせず、担当者設定と同時に完了できるよう詳細モーダルを自動で開く

### 2.5 担当者割り当て機能

- 問い合わせ詳細画面から、担当スタッフをプルダウンで選択・変更できる
- 初期状態は「未割り当て」とする
- スタッフアカウントの削除機能は設けない(小規模な運用を想定しているため)

### 2.6 優先度設定機能

- 詳細画面から「高・中・低・未設定」を選択できる
- 初期値は「未設定」とする。ただし2.7の自動設定機能によりキーワードが検出された場合、登録時点でDB上の優先度に「高」を保存する(ボードの強調表示・優先度順ソート・統計に反映するため)
- キーワード検出により自動設定された場合、対応履歴に「キーワード検出により優先度を『高』に自動設定しました」と自動記録し、スタッフによる確定操作と区別できるようにする
- 顧客側では優先度を設定できず、スタッフのみが最終的に変更・確定できる

### 2.7 優先度自動設定機能

- 問い合わせ内容に、以下のいずれかのキーワードが含まれる場合、登録時点で優先度を「高」に自動設定する
  - 緊急性を示す語：至急、緊急、今すぐ、早急に
  - 不満・苦情を示す語：クレーム、苦情、不満
  - 深刻な状態を示す語(SaaS想定)：ログインできない、使えない、解約したい、決済エラー
- 「対応してほしい」等、通常の要望でも使われる表現は誤検知(過剰な「高」判定)を招くため対象外とする
- 自動設定後も、スタッフが最終的に変更・確定できる

### 2.8 対応履歴・コメント機能

- 問い合わせ詳細画面に、システムによる自動記録(ステータス変更・担当者変更・優先度変更)と、スタッフが手動で入力するコメントを、同一の時系列リストで表示する
- コメントはスタッフが自由入力し、投稿者(スタッフ名)と日時を記録する
- 問い合わせ登録時、最初のシステム記録として「問い合わせを受け付けました」を自動で1件追加する

### 2.9 経過時間警告表示機能

- 「未対応」ステータスのまま、受付から24時間以上経過した問い合わせを一覧上で赤色等に強調表示する
- ステータスが「対応中」「完了」になった場合、強調表示を解除する
- 経過時間は常に受付日時(`created_at`)を起点に判定する。ステータスが「未対応」に後戻りした場合も、起点は最初の受付日時のままとし、リセットしない

### 2.10 統計ダッシュボード機能

- ボード画面上部に、ステータス別件数(未対応/対応中/完了)を棒グラフで表示する
- カテゴリ別件数も同様に集計表示する

### 2.11 担当者別対応件数可視化機能

- スタッフごとに、未完了件数(ステータスが「未対応」+「対応中」の合計)を一覧表示する
- 画面上のラベルは「未完了件数」とし、ステータス名の「対応中」と混同しないようにする
- 動作確認・デモ用に、複数のダミースタッフアカウントを用意して確認する

### 2.12 並び替え機能

- デフォルトは受付日時順(古い順)で表示する
- 「優先度順」ボタンを押すと、優先度(高→中→低→未設定)順に並び替える。再度押すと受付日時順に戻る
- 並び替えの状態はカラムごとに独立して保持する(例:「未対応」カラムだけ優先度順にしても、「対応中」「完了」カラムには影響しない)
- カード位置の手動ドラッグによる並び替え(position順)は設けない

### 2.13 メール通知機能

- 問い合わせ登録時、ActionMailerにより確認メールの内容を生成する
- 開発環境では`letter_opener`によりブラウザでプレビュー確認する
- 本番環境での実際の外部送信(外部メールサービス連携)は今回のスコープには含めない。環境ごとに配送方法を切り替え可能な設計とする

## 3. バリデーション一覧

| フィールド | 必須/任意 | ルール |
|-----------|------------|--------|
| 氏名 | 必須 | 空欄不可・255文字以内 |
| メールアドレス | 必須 | メール形式であること・255文字以内 |
| 電話番号 | 任意 | 20文字以内 |
| カテゴリ | 必須 | `料金プラン` / `使い方` / `解約` / `不具合` / `その他` のいずれか |
| 問い合わせ内容 | 必須 | 空欄不可・制限なし |
| ステータス | 必須 | `未対応` / `対応中` / `完了` のいずれか |
| 優先度 | 任意 | `未設定` / `高` / `中` / `低` のいずれか |
| コメント内容 | 必須(コメント投稿時) | 空欄不可・制限なし |
| スタッフのメールアドレス | 必須 | 一意であること・255文字以内 |
| スタッフのパスワード | 必須 | 8文字以上 |

## 4. ユースケース

| ユースケース | 操作の流れ |
|---|---|
| 問い合わせを送信する | ①顧客がフォームに入力 → ②送信 → ③完了画面が表示される |
| ログインする | ①スタッフがログイン画面でメール・パスワードを入力 → ②ボード画面に遷移する |
| 問い合わせを確認・対応する | ①ボード画面でカードを確認 → ②クリックして詳細を開く → ③内容を確認しコメントを残す |
| ステータスを変更する | ①カードをドラッグ&ドロップ(PC)、またはプルダウンで選択(スマホ) → ②ステータスが更新される |
| 担当者を割り当てる | ①詳細画面を開く → ②担当者プルダウンから選択 → ③保存する |
| 対応漏れを確認する | ①ボード画面で赤く強調されたカードを確認 → ②優先的に対応する |
